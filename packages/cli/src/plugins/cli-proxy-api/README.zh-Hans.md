# CLIProxy 提供方

CLIProxy 提供方让一个 CordisX 应用可以连接多个显式配置、兼容 CLIProxyAPI 的提供方，并在独立页面中选择模型、创建会话、搜索提供方历史、继续工作和管理会话生命周期。它不会替换 Codex Desktop 的原生会话。

## 打开提供方会话

从 **提供方** 导航入口进入外部提供方会话列表，也可以在 Manager 的路由目录中打开“提供方会话”路由。路由元数据说明入口位置，页面元数据说明主工作区内可用的模型和会话操作。

规范路由 id `providers.sessions`、路径 `/main/providers/sessions`、outlet `main` 和页面 id `providers.sessions` 都是稳定且不翻译的机器标识。只有面向用户的标题和说明跟随 CordisX 当前界面语言。

## 配置提供方

打开 **插件 → CLIProxy 提供方 → 配置管理**。这是提供方连接的唯一产品入口；CordisX 不提供全局的“提供方”“运行时”“启动器”或“演示”设置页。

**提供方连接**分组保存运行时提供方列表，包括稳定的 `providerId`、显示名称、HTTPS 端点、启用状态、超时和提供方本地模型映射。保存后只重启外部提供方 Fleet。**下次启动**分组保存可选的可执行文件和隔离的数据目录，在应用重启后生效。

凭据必须作为 Host 管理的安全引用提交，例如获准的 `host-secret:` 引用。凭据值不会出现在插件、渲染器元数据、App Server 参数或本文档中。远程端点必须使用 HTTPS；只有回环地址的本地提供方可以使用 HTTP。

Manager 的 **配置管理** 标签只展示该插件自己的渲染行为：

- `providerIds` 默认为 `[]`，用于把页面过滤为 launcher 已配置并启用的提供方；空列表展示全部已启用提供方。最多可填写 64 个 id，每个都使用与 launcher 相同的小写格式 `[a-z0-9][a-z0-9._-]{0,95}`。
- `defaultCwd` 默认为 `""`，用于预填新会话的工作目录；空值时可在提供方页面选择目录。最大长度为 4096 个字符，且不能包含 NUL。

非法配置由 Host 的、绑定 profile 和 generation 的 CAS 服务配置 API 拒绝。发生 revision 冲突时必须先重新检查再保存。权限拒绝会明确显示为权限拒绝，而不会伪装成校验失败。插件不会获得 home 配置写入器、凭据值、进程句柄、选择器或原始 bridge。

提供方 id 是持久身份，不是显示名称。创建会话后请保持每个 id 唯一且稳定。

## 模型与会话身份

每个模型由 `providerId` 与 `modelId` 共同标识；每个会话由 `providerId` 与远端 session id 共同标识。模型和会话结果会同时显示提供方，因此两个网关即使返回相同模型或会话 id，也不会冲突、恢复错误会话或混合搜索结果。

## 外部提供方与原生连接

外部提供方 Fleet 与 Codex Desktop 当前原生连接彼此独立。它不会冒充原生连接、把原生会话导入提供方页面，也不会在原生工作失败时自动回退到外部提供方。因此，外部提供方健康并不会改变“当前原生连接不可用”的状态，原生会话仍保留在原有 Codex 界面中。

## 权限

插件使用标准 CordisX 权限流程。插件详情会展示以下能力的策略和本次运行审计信息：

- `models.read`：列出提供方模型；
- `tasks.catalog.read` 与 `tasks.content.read`：列出、搜索和打开会话；
- `tasks.create` 与 `tasks.control`：创建、继续、派生、归档、恢复或删除会话；
- `turns.submit` 与 `turns.control`：提交、引导或中断 turn。

请在 **插件 → CLIProxy 提供方 → 权限** 中检查这些能力。被拒绝的能力会保持拒绝；插件不会绕过 broker，也不会回退到原生连接。

## 空状态与不可用状态

没有已启用提供方时，不会显示外部模型或会话。请打开 CLIProxy 提供方插件详情添加连接。已配置提供方不可用时，请检查端点、安全凭据引用、网络访问和 Codex 可执行文件。其他提供方身份仍保持隔离，不可用提供方绝不会被另一个提供方静默替换。

## 当前边界

CordisX 与该内置插件都是实验性、非官方、需显式启用的本地软件。兼容性取决于所配置的 CLIProxyAPI 兼容端点和已安装 Codex app-server 的行为，不承诺支持所有网关版本或模型工作流。凭据始终留在 launcher 侧；插件只接收经过权限 broker 的提供方操作和面向用户的结果。
