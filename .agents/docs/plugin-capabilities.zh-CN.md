# 插件能力边界与贡献方式

CordisX 插件是可独立构建、安装和分享的项目。判断一个需求应该做成插件，
还是先建设平台能力，只需要看它能否通过公开、版本化的 CordisX 接口完成。

## 插件能做什么

插件可以通过公开接口声明和实现：

- 命令、操作、插槽和集合项；
- 路由、页面和 CordisX 管理器内容；
- 配置结构、权限请求、本地化文案和宿主图标；
- 业务状态，以及已获授权的平台或 Agent 能力调用。

插件负责业务逻辑和数据，CordisX 负责渲染、生命周期、权限与宿主适配。

## 插件不能做什么

插件不能绕过 CordisX 直接修改 Codex DOM、私有 React 树或未公开接口，也不能
自行替换宿主导航、页面外壳、主题、无障碍行为或权限策略。公开能力不存在时，
插件应明确说明暂不支持，不能用私有 Hook 或隐藏的 DOM 补丁伪造实现。

## 缺少能力怎么办

如果需求缺少扩展点、事件、数据、服务或宿主适配，可以先在
[CordisX Issues](https://github.com/cordisx/cordisx/issues) 提出具体使用场景，再提交
PR，把它建设为最小、通用、带版本的公共能力。公共协议与 Host 实现应包含
生命周期、权限、本地化、无障碍、测试和文档；能力发布后，插件再通过公开接口
使用它。

如果缺少的是与具体宿主无关的上下文、服务组合或生命周期原语，可以向底层
[Cordis](https://github.com/deepseek-ai/DeepSeek-Harness) 贡献。不要为了绕过平台边界
而把宿主私有实现放进 Cordis。

提交代码前请阅读 [贡献指南](../../CONTRIBUTING.md)。
